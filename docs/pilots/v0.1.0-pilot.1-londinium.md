## Load test (shared criterion 3)

Installed with:

```sh
npx skills add crisesarmiento/cstack@v0.1.0-pilot.1 -s correct -s sharpen
```

`correct` and `sharpen` loaded in OpenCode 2.3.2, Claude Code 2.1.330 and
Codex 0.171.0 (3 of 5). Claude Code saw the skills through `.claude/skills`
symlinks; it does not read `.agents/`. Cursor Agent (2026.11.19) was not run
because `agent login` was missing. pi (1.6.0) was not run because no model
was configured. Those two remain open.

## sharpen

Each run used the minimal prompt `Implement #N. Use implementar-issue and
tests-primero.` on a worktree pinned to the commit just before the real
implementation PR, without reading that PR. The rewritten prompt was compared
with what the merged PR actually needed.

Londinium [#370](https://github.com/Palehour/londinium/issues/370)→[#374](https://github.com/Palehour/londinium/pull/374)
and [#352](https://github.com/Palehour/londinium/issues/352)→[#358](https://github.com/Palehour/londinium/pull/358)
passed. [#350](https://github.com/Palehour/londinium/issues/350)→[#359](https://github.com/Palehour/londinium/pull/359)
passed with a gap: the prompt did not ask the loader to validate new `data/`
keys, which #359 needed a fix commit for. All three runs produced a
restatement, the four answers, an objective check and owner choices left as
choices; each exited 0 in about 95 s and changed no files. That covers the
three sharpen criteria in spec 0002. Detail is in the table in #8.

## correct

### First seeding (data keys without loader validation)

Seeded with the suspected class "new `data/` keys added without loader
validation", citing Londinium #374 and #359.

The result was an honest negative. correct rechecked the evidence: #359
counts; #374 does not, because those keys arrived together with their
validation. One occurrence is below the two-case threshold, so it added no
rule, changed no files and made no commits. It also corrected a wrong reading
by the person who seeded it.

### Run on Londinium #385 T1

The T1 implementation added `tools/verificar.gd`, `tools/verificar.sh` and
`tools/verificar.ps1`, plus 25 tests in `tests/tools/test_verificar.gd`. It
landed in [Palehour/londinium#389](https://github.com/Palehour/londinium/pull/389),

[issue #12](https://github.com/crisesarmiento/cstack/issues/12) and

### pilot-correct-2

This run produced Londinium issue
[#397](https://github.com/Palehour/londinium/issues/397) and
[PR #398](https://github.com/Palehour/londinium/pull/398): a GDScript UID
check (`tools/check_script_uids.sh`, hooked from `tools/check_gdscript.sh`)
and market price bounds validated by key shape rather than per registered
good. The PR was merged into `develop` as f835ac7 on 2026-11-24 at 21:48
(America/Cordoba). cstack itself was not adopted on `develop` (D-199).

PR #398's body demonstrates a fail-then-pass check for both hardenings:

- UIDs: with `GIT_INDEX_FILE` pointing at historical commits `aaab298`,
  `3af729c` or `1da8438`, `bash tools/check_script_uids.sh` exits 1 (missing
  companion `.uid`). On later commits that have the companion, and on the
  PR head, it exits 0 (`ok (323 scripts checked)`).
- Prices: before the refactor,
  `test_market_price_bounds_apply_without_per_good_registration` failed
  because `market.another_good.{base,min,max}_price` accepted `-1` and
  overflow. After the refactor, that test exits 0 (37 asserts).

That ticks the fail-then-pass item that #8 still listed as untested after
the first seeding.

## Recommendations for v0.2

- **sharpen:** consider adding the question "are there new data keys the
  loader must validate?". It appeared once (#350→#359), so this is a
  candidate, not a rule.
- **correct:** require each new rule to ship with a check that fails on the
  past error and passes on the fix. Keep the two-case threshold.
- **Installation:** state explicitly that Claude Code needs the
  `.claude/skills` symlinks, because it does not read `.agents/`. The
  installer already creates those links; the load test is why they matter.
- **Pilot method:** one worktree per experiment, pinned to the pre-PR
  commit, and check that no processes are running in it before moving HEAD.
  A detached HEAD briefly broke a live test during this pilot.
- **Issue #8:** once this writeup is accepted, close #8 with the results
  that exist and, if Cursor Agent and pi are still blocked, move those load
  tests and the second-agent verify-template run to v0.2.
